\section{Introduction}

The purpose of this project is to design and implement a Multi-Agent System (MAS) that detects possible conflicts in air traffic control (ATC). The system analyses a simulated airspace, with multiple aircraft and their flight plans, and identifies the conflicts that may occur because of the minimum separation distances and the airspace constraints. Then it suggests safe manoeuvres to solve these conflicts before they happen.

The system takes three required inputs, as defined in the assignment. The first is a graph of the airspace in GraphML format, with the waypoints and the distances between them. The second is an aircraft file in JSON format, with the ID and speed of each aircraft. The third is a flight plans file in JSON format, with the route, departure time and cruise altitude of each aircraft. In addition, each scenario can include three optional files that we added: a stored weather snapshot, restricted or military zones with their active hours, and airport constraints such as closures or ground stops. All the information is provided in advance, as the system is based on a static model.

The output is an Air Traffic Control report in Markdown. It describes the scenario, lists the conflicts found with the reason for each one, and explains the manoeuvres proposed to solve them. It also shows which manoeuvres were approved by the Safety Validation crew, which conflicts need a human controller, and which flight plans were rejected because they were invalid.

Our MAS has six crews: the four required by the assignment and two additional ones. The Data Management Crew processes and normalises the data. The Airspace Constraints Crew turns the weather, the restricted zones and the airport constraints into zones that aircraft must avoid. The Surveillance \& Conflict Crew detects conflicts between aircraft and between aircraft and those zones. The Tactical Resolution Crew proposes manoeuvres to solve them, and the Safety Validation Crew checks every manoeuvre before it is accepted. Finally, the Reporting Crew writes the report. The system uses CrewAI Flows and Routers: if conflicts are detected, the Tactical Resolution and Safety Validation crews run before the report, and rejected manoeuvres go back to Tactical Resolution at most twice; if there are no conflicts, the flow goes straight to the Reporting Crew.
